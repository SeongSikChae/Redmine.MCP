# 첨부파일 다운로드 MCP 도구 — 방안

## 문제

- `get_issue(include=attachments)`는 첨부 메타데이터만 반환한다: `id`, `filename`, `filesize`, `content_type`, `content_url`.
- MCP만으로는 파일 본문(바이너리/텍스트)을 받을 수 없다. 에이전트가 API 키를 찾아 Shell로 `attachments/download/{id}`를 호출해야 한다.

## 목표

- 서버 YAML에 설정된 Redmine API 키로 첨부 본문을 내려받는 MCP 도구를 추가한다.
- 에이전트는 Shell·키 탐색 없이 본문을 읽거나(로컬 MCP면) 지정 경로에 저장할 수 있다.

## 대안

| 대안 | 요약 | 채택 |
|------|------|------|
| A. 응답 본문만 | JSON에 텍스트/base64만 반환 | 부분 |
| B. 서버 경로 저장만 | `outputPath` 저장 후 경로만 반환 | 부분 |
| C. 본문 + 선택적 저장 | 기본 본문 반환, `outputPath` 있으면 저장 | **채택** |
| 업로드 포함 | `/uploads`·일감 첨부까지 | 비범위 |

## 채택 방안

### 도구

- 이름: `download_attachment`
- `ReadOnly = true`
- 새 도구 클래스(예: `AttachmentTools`) + `Program.cs` `.WithTools<>()` 등록
- 반환: 기존 도구와 같이 `Task<string>`(JSON 문자열)

### 입력

다음 중 **하나**로 첨부를 식별한다.

1. **`attachmentId`** (권장·기본)
2. **`issueId` + `filename`** — `GET issues/{id}.json?include=attachments`로 메타를 찾고 id를 해석. 동명 파일이 둘 이상이면 오류.

선택:

- **`contentUrl`** — 있으면 메타의 `content_url` 대신 이 URL로 본문 GET. **설정상 Redmine API endpoint와 같은 origin만 허용** (오픈 리다이렉트·외부 URL 방지).
- **`outputPath`** — 지정 시 MCP 서버 호스트 파일시스템에 바이트를 기록하고 응답에 `savedPath`를 포함한다.

`attachmentId`와 `issueId`+`filename`이 모두 없으면 오류. 둘 다 있으면 `attachmentId`를 우선한다.

### 출력 (방안 C)

JSON 필드:

| 필드 | 설명 |
|------|------|
| `id` | 첨부 id (알 수 있으면) |
| `filename` | 파일명 |
| `contentType` | Content-Type |
| `filesize` | 바이트 크기 |
| `text` | 텍스트로 취급할 때 UTF-8 본문 |
| `contentBase64` | 바이너리(또는 텍스트 미취급)일 때 |
| `savedPath` | `outputPath`로 저장했을 때 실제 경로 |

`text`와 `contentBase64`는 동시에 두지 않는다.

### 텍스트 vs base64

다음이면 `text`, 아니면 `contentBase64`:

- `content_type`이 `text/`로 시작
- 또는 `application/json`, `application/xml`, `application/javascript`, `application/yaml`, `application/x-yaml`
- 또는 확장자가 `.md`, `.txt`, `.csv`, `.json`, `.xml`, `.yaml`, `.yml`, `.log`, `.textile`

UTF-8 디코딩 실패 시 `contentBase64`로 내린다.

### 인라인 크기 상한

- **상한: 5 MiB** (5 × 1024 × 1024 바이트)
- 본문 크기 > 상한이고 `outputPath` 없음 → 오류(인라인 거부, `outputPath` 지정 안내)
- 본문 크기 > 상한이고 `outputPath` 있음 → 디스크에만 저장, 응답은 메타 + `savedPath`만 (`text`/`contentBase64` 생략)
- 본문 크기 ≤ 상한 → 메타 + `text` 또는 `contentBase64`; `outputPath`가 있으면 저장하고 `savedPath`도 포함

### Redmine 호출

1. 식별: `attachmentId` 또는 일감+파일명 해석
2. 메타 필요 시: `GET attachments/{id}.json` → `filename`, `content_type`, `filesize`, `content_url`
3. 본문: `GET content_url`(또는 허용된 `contentUrl`) — `X-Redmine-API-Key` 사용, JSON 전용 `Accept`를 쓰지 않음(또는 `*/*`), 바이트로 수신

현재 `RedmineClient`는 문자열 GET만 있고 `Accept: application/json`이 고정이므로, 설계·구현 단계에서 바이너리 GET(요청별 Accept) 확장이 필요하다.

### `outputPath` 주의

- 경로는 MCP **서버 프로세스**가 도는 호스트 기준이다. 원격 MCP에서는 에이전트 PC에 파일이 생기지 않는다.
- 로컬 MCP(`localhost`) 사용을 전제로 한 편의 기능이다.

## 비범위

- 첨부 업로드 (`POST /uploads`, 일감 `uploads` 연결)
