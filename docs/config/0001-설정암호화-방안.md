# 설정 보안정보 암호화 — 방안

## 문제

- YAML 설정의 `ServerCertificatePassword`, `RedmineApiKey`가 평문으로 상시 보관된다.
- 설정 파일 유출·백업·저장소 복사 시 인증서 암호와 Redmine API 키가 노출된다.

## 목표

- 기동 시 Azure Key Vault KEK + 로컬 DEK(`Biz.Bizadm.KMS`)로 민감 필드를 암호화·복호화한다.
- 설정 파일에는 암호문만 남기고, 런타임(PFX 로드, HTTP 헤더)에만 평문을 쓴다.
- 설정 모델을 CTI.MCP와 같이 `Secure` / `AzureKms` / `Redmine` 중첩으로 맞춘다.

## 대안

| 대안 | 요약 | 채택 |
|------|------|------|
| A. Azure KMS(KEK+로컬 DEK) | `Biz.Bizadm.KMS`, 기동 시 Encrypt-if-needed → YAML 갱신 → Decrypt | **채택** (규칙 `dotnet/azure-kms-config-secrets`) |
| B. DPAPI / UserSecrets | 머신·사용자 로컬만, Azure KEK 없음 | 비범위 |
| C. 환경변수만 | 파일 평문 제거, 암·복호화·감사 체계 없음 | 비범위 |
| D. 자체 AES 유틸 | 저장소 규칙 위반 | 비범위 |

## 채택 방안

### 라이브러리·키

- `Biz.Bizadm.KMS`: `AzureKeyVaultKekManager`, `DekCipherService`, `AesGcmDekCipher`
- KEY_NAME: `RedmineMCPKey`
- 자격 증명: `CurrentUser\My` 클라이언트 인증서 지문 → `ClientCertificateCredential`
- DEK 경로: `ContentRootPath` + `AzureKms.SecretsDekFilePath`
- 참고: CTI.MCP `Configuration.cs`, `Program.cs` 기동부, `Configuration.sample.yml`

### 설정 구조

기존 flat YAML은 **운영자가 수동 마이그레이션**한다(자동 변환 도구 없음).

```yaml
ContentRootPath: ...
Port: ...
Secure:
  UseSsl: ...
  ServerCertificate: ...
  ServerCertificatePassword: ...  # 기동 시 암·복호화
  # CertificateChain / IncludeCipherSuites 선택
AzureKms:
  ClientCertificateThumbprint: ...
  AzureTenantId: ...
  AzureClientId: ...
  AzureKeyVaultUrl: ...
  SecretsDekFilePath: ...  # ContentRootPath 기준
Redmine:
  RedmineApiEndpoint: ...
  RedmineApiKey: ...  # 기동 시 암·복호화
```

모델:

- `SecureConfiguration` — SSL 필드 + `Validate`(UseSsl 시 인증서·암호 required)
- `AzureKmsConfiguration` — 위 5필드 전부 required
- `RedmineConfiguration` — `RedmineApiEndpoint`, `RedmineApiKey` required
- 루트 `Configuration` — `ContentRootPath`, `Port`, 세 섹션 + nested Validate

### 기동 흐름

1. YAML 역직렬화 → `ConfigurationValidator.Validate`
2. 지문으로 인증서 조회(`HasPrivateKey`) → 없으면 기동 실패
3. `ClientCertificateCredential` → `AzureKeyVaultKekManager.CreateAsync(..., KEY_NAME)`
4. `DekCipherService` + `AesGcmDekCipher.Create(manager.Current, dekFile)`
5. 민감 필드별:
   - `StartsWithFromPrefix == false`(평문): `Encrypt` → YAML 재직렬화·저장
   - 이후 런타임용 `Decrypt`
6. `CreateWebApplication` — 복호화된 값만 사용

민감 필드:

- `Secure.ServerCertificatePassword` — null이면 건너뜀
- `Redmine.RedmineApiKey` — 항상 Encrypt-if-needed → Decrypt

### 문서·샘플

- `Configuration.sample.yml`에 placeholder와 “기동 시 Azure KMS로 암호화·복호화” 주석
- 실제 시크릿·지문·Vault URL은 저장소에 커밋하지 않음
- README에 중첩 구조·암호화 동작을 반영
