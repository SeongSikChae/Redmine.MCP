# 설정 보안정보 암호화 — 설계

근거: [0001-설정암호화-방안.md](0001-설정암호화-방안.md) (`status: done`)

미합의 항목은 쓰지 않는다. 합의된 결정만 아래에 누적한다.

## 합의된 결정

### D1. 기동 부트스트랩 위치 — **A**

- [`Program.cs`](../../src/Redmine.MCP.Server/Program.cs) `Main`에 CTI.MCP와 같이 인라인으로 둔다.
- 인증서 조회 → `ClientCertificateCredential` → `AzureKeyVaultKekManager`(`KEY_NAME = "RedmineMCPKey"`) → `DekCipherService` / `AesGcmDekCipher` 순서는 방안과 동일하다.
- 부트스트랩 전용 헬퍼 클래스는 추가하지 않는다.

### D2. YAML rewrite 시점 — **B**

- 민감 필드(`Secure.ServerCertificatePassword`가 평문인 경우, `Redmine.RedmineApiKey`가 평문인 경우)를 먼저 모두 `Encrypt`한다.
- `StartsWithFromPrefix`로 이미 암호문인 필드는 Encrypt하지 않는다. `ServerCertificatePassword`가 null이면 건너뛴다.
- 하나라도 Encrypt가 발생했을 때만 `YamlDotNet` `Serializer`로 `ConfigFilePath`를 **한 번** 덮어쓴다.
- rewrite 이후(또는 Encrypt가 없었던 경우) 해당 필드들을 일괄 `Decrypt`하여 인메모리 `configuration`에 런타임 평문을 둔다.

### D3. 소비처 갱신 — **A**

- flat → 중첩에 맞춰 필수 경로만 수정한다. 호환 래퍼·확장 프로퍼티는 추가하지 않는다.
- `Program.CreateWebApplication`: `configuration.Secure!.*` (UseSsl, ServerCertificate, ServerCertificatePassword, CertificateChain, IncludeCipherSuites)
- [`RedmineHttpClientSetup`](../../src/Redmine.MCP.Server/Redmine/RedmineHttpClientSetup.cs): `configuration.Redmine!.RedmineApiEndpoint` / `RedmineApiKey`
- 테스트 인메모리 `new Configuration { ... }`도 같은 중첩으로 맞춘다. KMS 부트스트랩은 테스트에 넣지 않는다.

### D4. 샘플·README — **A**

- `Configuration.sample.yml`을 추가하고 CopyToOutputDirectory로 둔다. placeholder와 “기동 시 Azure KMS로 암호화·복호화” 주석을 넣는다.
- 루트 [`README.md`](../../README.md)와 [`src/Redmine.MCP.Server/README.md`](../../src/Redmine.MCP.Server/README.md) 설정 절을 중첩 YAML·암호화 동작으로 갱신한다.
- 실제 시크릿·지문·Vault URL은 커밋하지 않는다. 기존 flat YAML은 수동 마이그레이션.
